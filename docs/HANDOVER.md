# НА МЕСТЕ — передача проекта исполнителю

Дата: 12.11.2026. Документ для разработчика, который дорабатывает приложение. Читать вместе с
[README.md](../README.md). Секретов в этом файле нет — только названия настроек и где их взять.

## 1. Что это
Веб-приложение для развозки детей по Петербургу, ставится на экран «Домой» iPhone. Три роли в одном приложении:

| Роль | Адрес | Что делает |
|---|---|---|
| Родитель | `/app` | «Запланированные поездки»: неделя, дети, «+» новая поездка, «Отсутствие ребёнка», чат, профиль (места) |
| Водитель | `/driver` | смена по точкам, «Еду сюда» → «Я на месте» → посадка/передача, неделя вперёд |
| Диспетчер | `/admin` (компьютер), `/admin/inbox` (телефон) | входящие просьбы и заявки, рейсы на день, семьи, водители, чат |

Боевой адрес: https://na-meste-spb.ru (старые `nameste-spb.duckdns.org` и `www.` перенаправляются).

Стек: TypeScript; сервер — Node 22, Fastify, SQLite (better-sqlite3) через Drizzle ORM, zod;
веб — React 19, react-router 7, Vite; тесты — Vitest; карта — MapLibre.

## 2. Быстрый старт
```bash
npm install
npm run seed       # выдуманная семья «Маша и Лёва», машина, неделя поездок; печатает коды входа
npm run dev        # сервер :3000 и приложение http://localhost:5173
npm test           # 72 теста
npm run typecheck
npm run build      # сборка веб-приложения в dist/web
```
Миграции базы лежат в `server/db/migrations` и применяются сами при старте сервера. Новая миграция:
изменить `server/db/schema.ts` → `npm run db:generate` → **проверить сгенерированный SQL** (при пересоздании таблицы
drizzle однажды выбирал несуществующие колонки — см. `0007_place_change.sql`) → прогнать на копии базы.

## 3. Карта кода
| Где | Что |
|---|---|
| `server/index.ts` | точка входа, защита запросов, регистрация маршрутов |
| `server/routes/*` | HTTP: `parent`, `driver`, `admin`, `admin-edit`, `chat`, `public` (вход), `leads`, `track`, `tracker`, `yandex-auth` |
| `server/modules/*` | вся логика: `planner` (рейсы), `rides`, `schedule` (повторы), `changes` (просьбы родителей), `requests` (заявки на поездки), `leads` (заявки из Телеграма), `notify`, `geo`, `tracking`, `chat`, `auth`, `jobs` (фоновые задачи, ночные копии) |
| `server/db/schema.ts` | вся схема базы |
| `shared/*` | то, что нужно и серверу, и вебу: типы API, время, повторы, тексты, цены |
| `web/src/pages/{parent,driver,admin}` | экраны ролей; `web/src/components` — общие части (`ui.tsx`: Sheet, Toast, Skeleton) |

| `scripts/*` | выкладка, откат, копия базы |

## 4. Боевой сервер и выкладка
- Сервер (Яндекс Облако, Ubuntu 24.04): `root@81.29.141.215`, SSH-порт 22. Код — `/opt/na-meste`,
  база и ключи — `/var/lib/na-meste` (там же `na-meste.db` и ночные копии), сервис — `systemctl status na-meste`,
  HTTPS и редиректы — Caddy (`/etc/caddy/Caddyfile`). Внутренний порт приложения 3100.
- Выкладка: из папки проекта `bash scripts/deploy-prod.sh` — берёт текущую ветку, собирает, копирует на сервер,
  ставит зависимости, перезапускает сервис, проверяет `/api/health`. Предыдущая версия сохраняется:
  откат — `bash scripts/rollback-cloud.sh`.
- Копия базы на свой компьютер: `bash scripts/backup-pull.sh` (хранит 30 последних).
- Настройки сервера лежат в `/opt/na-meste/secrets.env` (в git не попадает). Перенос файла на сервер делает
  скрипт выкладки; **сами значения владелец передаёт отдельно**, не в переписке.

### Настройки (названия; значения — у владельца)
`PUBLIC_URL`, `PORT`, `DATA_DIR`/`DB_FILE`, `NODE_ENV`; режимы `LITE_MODE` (простой режим: без карты, цен и слежения —
сейчас включён), `DEMO_MODE`/`DEMO_KEY` (демо-вход, на боевом выключен); вход `MASTER_CODE_SHA256`, `MASTER_PHONE`,
`ADMIN_PHONES`, `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `YANDEX_LOGIN`; почта `MAIL_PROVIDER`, `SMTP_*`, `MAIL_EVENTS`;
SMS `SMS_PROVIDER` (по умолчанию выключено), `SMSRU_API_ID`, `YC_SMS_*`; карты `OSRM_URL`, `NOMINATIM_URL`;
`VAPID_SUBJECT` (ключи push создаются сами и лежат в каталоге данных); заявки из бота `LEADS_SECRET`.
Шаблон — `secrets.env.example`, `.env.example`, `bot.env.example`.

## 5. Правила продукта (не менять без согласования с владельцем)
1. **Все самостоятельные действия родителя утверждает диспетчер** — он один знает возможности водителей:
   отмена и перенос поездки, «Отсутствие ребёнка», смена адреса места, новая поездка. Название места и «как пройти»
   родитель правит сразу (диспетчер и водители получают уведомление). Удалить место можно, только если по нему нет поездок.
   Родителю после просьбы 10 секунд доступно «Отменить» (просьба отзывается).
2. **Причина отмены не выбрана заранее**: без неё отправить нельзя.
3. **Родитель без поездок видит** «Запланируйте поездки своего ребёнка» и «+» — второй кнопки заказа нет.
4. **Главная родителя — по замечаниям Анастасии** (партнёр, LeStart): заголовок «Запланированные поездки»;
   «Сегодня» — строка состояния, не кнопка; неделя на главной; фильтр по детям; «+» в углу; кнопка «Отсутствие ребёнка»;
   нижняя панель только «Профиль» и «Чат»; чата на главной нет. Решения принимает владелец — Анастасия важнее моих идей.
5. Дизайн: тёмно-синий `#1b3440`, кремовый, золото `#b38a4a`; шрифты Geologica (заголовки) и Golos Text.
   Принцип «меньше»: одно главное действие на экране, метка статуса — только у особого статуса, поясняющих строк минимум.
6. Роль видна по экрану; полосы ролей нет. Переключатель режимов — раздел «Режим» в «Профиле», «Ещё» диспетчера
   и на главной водителя. У диспетчера на телефоне вкладки «Входящие · Сегодня · Семьи · Ещё».

## 6. Что сделано и что отложено
**Сделано:** вход по коду (8 ячеек, вставка из буфера, автовход по ссылке), мастер-код диспетчера, несколько водителей и
рейсы по каждому, просьбы родителей через диспетчера, правка мест родителем, подсказки адреса и мини-карта, чат семьи,
«Входящие» диспетчера, заявки новых семей из Телеграм-бота, ночные копии базы, адаптация под телефон (проверено на 30 экранах).

**Отложено (порядок по важности):**

   api.telegram.org (боевой сервер в России не достаёт) — `docs/TELEGRAM-BOT.md`.
2. **Если приложение станет массовым** (список замечаний «Apple», 12.11): настоящее приложение для iPhone с push и Live Activity,
   «Вход через Apple» (у нас есть вход через Яндекс), удаление аккаунта и политика конфиденциальности в приложении,
   заявка новой семьи прямо со стартовой страницы, размер текста по настройкам iPhone (шрифты заданы в px),
   учёт «Уменьшить движение» для пульсирующей точки, английский язык, фото водителя и кодовое слово при передаче ребёнка,
   платная карта и геокодер вместо бесплатных (Nominatim — 1 запрос в секунду), второй сервер и наблюдение.
3. Мелочи интерфейса: заголовки таблицы «Сегодня» у диспетчера 11 px; буквы в кружках детей 10 px; галочка в настройках

4. `docs/ARCHITECTURE.md` написан 28.09 для домашнего сервера и Tailscale — **частично устарел**: боевой сервер теперь облачный
   (раздел 4 выше). Остальное (модули, схема) верно.
5. Обновить макет-концепт и колоду слайдов под правки Анастасии (в Claude-артефактах, не в репозитории).

## 7. Безопасность и данные
- В базе имена детей, адреса, расписания, телефоны, координаты — **персональные данные (152-ФЗ)**. Разработка идёт на
  выдуманных данных (`npm run seed`). Живую базу исполнитель без соглашения о неразглашении не получает.
- Сессии — в httpOnly-cookie; запросы с чужих сайтов отклоняются; вход ограничен по частоте; мастер-код хранится хешем.
- Секреты не в git (проверено: ни в файлах, ни в истории). Перед передачей владелец меняет всё, что звучало в переписке:
  мастер-код диспетчера, ключ `NEWDB_KEY`, токены.
